### 3. Whether target and random matching were achieved

**Prompt-local norm matching was achieved.**

- Spider target: residual norm `25.36320877 → 25.36320686`; perturbation norm `23.18580246` (`result.json:275-283`).
- Spider random controls request `23.18580246` and achieve either that value or approximately `23.18580437`; residual norms differ by at most roughly \(2\times10^{-6}\).
- Byte target: residual norm exactly `27.87487030 → 27.87487030`; perturbation norm `5.88542843` (`result.json:3143-3151`).
- Byte random controls achieve approximately `5.88543034–5.88543081`, again within a few \(10^{-6}\).

The target-coordinate movement itself was not a literal swap. The implementation adds `strength * (swapped - before)` with strength 8 and then renormalizes (`scripts/spider_ant_demo.py:89-95`); an unnormalized literal swap would correspond to strength 1.

- On spider, movement has the advertised orientation:
  > source `2.8094 → -17.1821`; target `-0.8640 → 18.4397`.
- On byte, it has the **opposite semantic orientation**:
  > source `-0.5623 → 11.5392`; target `0.9790 → -11.1306`.

Thus the byte condition labeled “Spider→Ant” actually increases the Spider coordinate and decreases the Ant coordinate according to its own recorded diagnostics.

There is also no cross-prompt physical matching: spider receives a `23.19`-norm perturbation, while byte receives only `5.89`. The basis and projected token directions are recomputed independently inside each `evaluate_prompt` call (`scripts/spider_ant_demo.py:206-223`).

### 4. What the byte control establishes—and does not

It establishes that:

- Under the byte prompt’s own prompt-conditioned C=8 operation, a clean high-confidence `8` remains essentially unchanged.
- The byte response is stable under its much smaller `5.89`-norm matched random rotations.
- Therefore this is not evidence for a completely generic rule that the same coefficient C=8 always converts every answer `8` into `6`.

It does **not** establish that:

- A perturbation physically as large as the spider perturbation would leave byte unchanged.
- The same residual-space direction was applied to both prompts.
- A genuine Ant-directed move leaves byte unchanged: the recorded byte coordinates move toward Spider, not Ant.
- Clean answer strength was controlled. Byte begins much more confident than spider: \(p(8)=0.9834\), entropy `0.1208`, versus spider \(p(8)=0.8826\), entropy `0.5579`.
- Semantic specificity, as opposed to susceptibility of this particular spider completion, has been isolated.

### 5. Identical targeted and forced-6 generations

For spider, targeted and forced-first-`6` generations have exactly identical 64-token ID arrays (`result.json:2741-2901`). Both begin:

> `6. Hypothesis: The animal that spins webs has 6 legs. Is the hypothesis entailed by the fact?`

The prediction document explicitly required a difference for the continuation to count as independent semantic evidence (`slop/research/20260905_spider_ant_rank16_confirmation_predictions.md:13`).

Therefore the equality establishes that, under greedy decoding, the observed continuation is fully reproduced by merely forcing the first token to `6`. It provides **no independent downstream Ant-semantic evidence**.

It does not prove hidden states or next-token distributions were identical; only the greedy token sequence was. The generation hook also intentionally skips every cached one-token decoding step (`scripts/spider_ant_demo.py:99-104`), so this is primarily a prefill/first-answer-token intervention.

For byte, `targeted_matches_forced_6=False` is not informative about continuation semantics because targeted begins with `8`, while forced-6 begins token-wise with `6` and then completes it as `64`.

### 6. Bugs and misleading report fields

- **P1 — Byte is mislabeled as a Spider→Ant intervention.** Its own coordinates move Ant down and Spider up (`result.json:3143-3151`). Smallest fix: report coordinate orientation and require source decrease/target increase before applying that label.
- **P1 — The control is not perturbation-matched across prompts.** Spider distance is `23.1858`, byte distance `5.8854`, and directions are separately recomputed. Smallest fix: add a byte condition using a frozen spider-derived direction or explicitly calibrated equal absolute distance.
- **P2 — “Thoughts after Spider→Ant” overstates both fields.** These are top suppressed-score vocabulary tokens, not thoughts, and the after basis is re-extracted. Rename them and evaluate after-state scores with the original basis.
- **P2 — “Exceeded N/32” obscures ties and significance.** The code counts only strict `<` comparisons (`scripts/spider_ant_demo.py:298-300`). Byte has seven ties; spider has two controls above target. Report counts below/equal/above and an empirical p-value.
- **P2 — `random top-6` uses arbitrary top-k tie order.** Spider seed 27 is an exact 6/8 tie but is counted as top-6. Report strict top, tied top, and rank separately.
- **P2 — The byte `targeted_matches_forced_6=False` field is mechanically determined by differing first tokens and should be marked not applicable.
- **P2 — Reproducibility metadata has `"model_revision": null`** (`log.md:40`), so the remote model snapshot is not pinned.
- **P2 — “Coordinate swap” is misleading at C=8.** It is an eightfold extrapolation followed by norm restoration, not a literal source/target coordinate swap.

## Inference

### Credibility of Spider→Ant semantic steering

There is real evidence for a **sample-specific causal perturbation**:

- The spider answer robustly changes from `8` to `6`.
- Byte remains `8`.
- The spider target beats 30/32 same-distance random controls.
- The spider coordinate diagnostics move from source toward target.

But the stronger semantic interpretation is not established:

- The preregistered semantic criterion was at least 31/32 controls plus Ant-like after-readout tokens (`predictions.md:9`); the run achieved only 30/32 and no Ant-like tokens.
- Two random controls produce a stronger 6-vs-8 effect, and five make `6` top.
- The after-readout becomes more Spider-like, not Ant-like.
- The complete continuation is reproduced by forcing `6`.
- The byte comparison uses a four-times-smaller perturbation, a much stronger clean margin, a different prompt-derived direction, and coordinate movement opposite to Ant.
- The job label states that rank-16/C=8 was selected because it had already changed this same spider prompt (`job_138_status.json:96`), so this is not an independent out-of-sample confirmation.

The most credible present claim is: **a selected, prompt-conditioned L26 perturbation flips this spider prompt’s first answer token from 8 to 6 and is more effective than most—but not all—large random rotations.** Calling this confirmed Spider→Ant semantic steering is premature; prompt-specific answer perturbation remains the simpler explanation.

### Cheapest next discriminator

Keep the exact spider prompt and extracted spider basis, but perform a preregistered one-token animal-target sweep—e.g. verified single-token targets whose leg counts are 2 and 4 in addition to Ant’s 6. Calibrate every patch to the same achieved perturbation norm and explicitly require source-coordinate decrease plus target-coordinate increase. Only first-token logits are needed.

- Semantic steering predicts the answer tracks the target animal’s leg count across targets.
- Prompt-specific perturbation predicts arbitrary digit shifts or a persistent preference for `6`.

This requires only a few additional forward passes and is more diagnostic than another 64-token generation.

**BLOCK** as evidence of confirmed Spider→Ant semantic steering. **OK** as a valid exploratory record of a prompt-specific intervention, with the reporting qualifications above.
